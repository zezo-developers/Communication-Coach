# Communication Coach — Conversation Check API Documentation

Reference for the endpoints exposed by
[`ConversationCheckController`](../src/modules/conversation-check/controllers/conversation-check.controller.ts).

## Overview

These endpoints generate casual English assessment questions, determine whether
another assessment is due, submit a conversation for AI assessment, and check
DigitalOcean AI connectivity.

| Method | Endpoint                                        | Purpose                                                                      | Authentication   |
| ------ | ----------------------------------------------- | ---------------------------------------------------------------------------- | ---------------- |
| `POST` | `/conversation-check/generate-casual-questions` | Generate five casual English assessment questions                            | JWT bearer token |
| `POST` | `/conversation-check/check-conversation-test`   | Check whether completed report count matches the user's assessment threshold | JWT bearer token |
| `POST` | `/conversation-check/submit-conversation-test`  | Assess a conversation and create/update the user's conversation-check record | JWT bearer token |
| `POST` | `/conversation-check/test-digital-ocean`        | Test the configured DigitalOcean AI model                                    | JWT bearer token |

**Base URL:** `{BASE_URL}` — for example, `http://localhost:3000`.

AI question generation and assessment use the OpenAI Agents SDK configured
against DigitalOcean's OpenAI-compatible inference API. See
[`ai-configuration.md`](./ai-configuration.md) for the required settings.

There is no global route prefix. All three endpoints require the access token:

```http
Authorization: Bearer <accessToken>
Content-Type: application/json
```

All routes are `POST` routes. They use Nest's default success status,
`201 Created`, except `test-digital-ocean`, which returns `200 OK`. Send a JSON
body only to `submit-conversation-test`; the other endpoints do not require one.

## Shared types

```typescript
export type ConversationMessageRole = 'ai' | 'user';
export type ConversationLevel = 'beginner' | 'intermediate' | 'advanced';

export interface ConversationMessage {
  role: ConversationMessageRole;
  message: string;
}

export interface ConversationScores {
  sentenceFraming: number; // 0–5
  vocabulary: number; // 0–5
  grammar: number; // 0–5
  fluency: number; // 0–5
  coherence: number; // 0–5
  confidence: number; // 0–5
}

export interface UserConversationCheck {
  _id: string;
  userId: string;
  status: 'pending' | 'in_progress' | 'completed' | 'failed';
  lastConversation: ConversationMessage[];
  scores?: ConversationScores;
  overallScore?: number; // 0–5
  reCheckConversatonAt?: number;
  level?: ConversationLevel;
  strengths: string[];
  improvements: string[];
  assessedAt?: string; // ISO date
  createdAt: string; // ISO date
  updatedAt: string; // ISO date
}
```

## 1. Generate casual assessment questions

### `POST /conversation-check/generate-casual-questions`

Uses the AI agent to generate exactly five distinct, casual questions. The
questions use everyday topics and are intended to elicit enough English for
evaluating the user's level. The server validates the response and returns a
server error if the AI response is not exactly five non-empty strings.

**Request body:** none.

**Example request:**

```http
POST /conversation-check/generate-casual-questions
Authorization: Bearer <accessToken>
```

**Example response (`201 Created`):**

```json
{
  "questions": [
    "What do you like to do in your free time?",
    "Can you tell me about a meal you enjoy making?",
    "What kind of music do you usually listen to?",
    "Where would you like to travel, and what would you do there?",
    "What is something new you would like to learn?"
  ]
}
```

The exact wording varies because the questions are generated by AI.

## 2. Check whether another conversation test is due

### `POST /conversation-check/check-conversation-test`

Counts the authenticated user's reports with `completed` status and compares
that count with `reCheckConversatonAt` on their conversation-check record. If a
record exists and the values match, the endpoint advances the threshold by
seven and returns `true`; otherwise it returns `false`.

**Request body:** none. The user is identified from the bearer token.

**Example request:**

```http
POST /conversation-check/check-conversation-test
Authorization: Bearer <accessToken>
```

**Example response when due (`201 Created`):**

```json
true
```

**Example response when not due (`201 Created`):**

```json
false
```

The response is a bare JSON boolean, not an object. A missing assessment
record or a report count that does not equal the stored threshold returns
`false`.

## 3. Submit a conversation for assessment

### `POST /conversation-check/submit-conversation-test`

Sends the supplied conversation to the AI assessment agent. The agent assesses
the user's messages and returns scores for sentence framing, vocabulary,
grammar, fluency, coherence, and confidence, plus an overall score, level,
strengths, and improvements. The result is saved in the authenticated user's
`UserConversationCheck` document.

Each message must contain:

| Field     | Type   | Rules                               |
| --------- | ------ | ----------------------------------- |
| `role`    | string | Required; either `"ai"` or `"user"` |
| `message` | string | Required and non-empty              |

The `conversation` array must contain at least one message and at least one
message with role `"user"`. Send messages in conversation order. The endpoint
rejects unknown fields in the request.

**Example request:**

```http
POST /conversation-check/submit-conversation-test
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "conversation": [
    {
      "role": "ai",
      "message": "What do you like to do in your free time?"
    },
    {
      "role": "user",
      "message": "I like reading books and cooking new recipes."
    },
    {
      "role": "ai",
      "message": "What kind of books do you enjoy?"
    },
    {
      "role": "user",
      "message": "Mostly history books because I want to understand how people lived in the past."
    }
  ]
}
```

**Example response (`201 Created`):**

```json
{
  "_id": "6710f4ca58bc5f45a23d1001",
  "userId": "66f2a110d6e1244f57a10001",
  "status": "completed",
  "lastConversation": [
    {
      "role": "ai",
      "message": "What do you like to do in your free time?"
    },
    {
      "role": "user",
      "message": "I like reading books and cooking new recipes."
    },
    {
      "role": "ai",
      "message": "What kind of books do you enjoy?"
    },
    {
      "role": "user",
      "message": "Mostly history books because I want to understand how people lived in the past."
    }
  ],
  "scores": {
    "sentenceFraming": 4,
    "vocabulary": 4,
    "grammar": 4,
    "fluency": 3,
    "coherence": 4,
    "confidence": 4
  },
  "overallScore": 3.8,
  "reCheckConversatonAt": 8,
  "level": "intermediate",
  "strengths": [
    "Expresses ideas clearly using relevant vocabulary.",
    "Provides reasons to support opinions."
  ],
  "improvements": [
    "Practice using a wider range of sentence structures.",
    "Continue building fluency by giving longer spoken responses."
  ],
  "assessedAt": "2026-10-15T08:30:00.000Z",
  "createdAt": "2026-10-15T08:30:00.000Z",
  "updatedAt": "2026-10-15T08:30:00.000Z"

```

The example assessment values are illustrative; scores and feedback are
generated from the submitted conversation. Repeated submissions update the
existing record for the authenticated user rather than creating a second
record. The assessment threshold advances by seven for each successful
submission. A newly created document starts with the schema default of `1`,
then advances to `8` on its first submission.

## 4. Test DigitalOcean AI connectivity

### `POST /conversation-check/test-digital-ocean`

Runs a short, fixed prompt through the configured OpenAI Agents SDK provider.
This authenticated diagnostic endpoint requires no request body and returns
the configured model name and its response. It returns `500 Internal Server
Error` if DigitalOcean AI is not configured or the request fails.

**Example request:**

```http
POST /conversation-check/test-digital-ocean
Authorization: ******
```

**Example response (`200 OK`):**

```json
{
  "success": true,
  "provider": "DigitalOcean",
  "model": "llama3.3-70b-instruct",
  "response": "DigitalOcean AI is responding."
}
```

## Errors

Errors use Nest's standard exception response format. Frontend clients should
use the HTTP status and `message` field to handle failures.

**Invalid request example (`400 Bad Request`):**

```json
{
  "statusCode": 400,
  "message": [
    "conversation must contain at least 1 elements",
    "each value in nested property conversation must be either object or array"
  ],
  "error": "Bad Request"
}
```

The exact validation messages depend on which constraint failed. Other expected
failure cases include:

| Status                      | Cause                                                                                                         |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `400 Bad Request`           | Invalid request shape, invalid message role, empty message, or no user response in the submitted conversation |
| `401 Unauthorized`          | Missing, invalid, or expired JWT                                                                              |
| `500 Internal Server Error` | OpenAI is not configured, AI assessment/question generation fails, or an AI response cannot be validated      |
